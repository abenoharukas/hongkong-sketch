# 香港岛 / Hong Kong Island

目标在仓库根目录 README：一个真实的、完全离线的香港游戏。
运行时只读本地瓦片。下面的正交相机只在制作底图时用，游戏不加载线上地图。

底图是 Google Photorealistic 3D Tiles，用一台正交相机拍下来：

    hk/ortho.html        一台正交相机，Cesium 里画 Google 的三维瓦片
    hk/shoot.mjs         无头 Chrome 逐个窗口截图（CDP）
    hk/build.py          拼成一张、刷水色、做色块底图、重绘、切瓦片
    hk/map.html          查看器

## 出图四步

    # 1. 底图：正交相机，每个窗口平移正好一个窗口宽
    node hk/shoot.mjs --out hk/source/plate --cols 6 --rows 4 --w 1024 --h 1024 \
      --mpp 1.1 --lon 114.1600 --lat 22.2770 --az -15 --tilt 45

    # 2. 拼版 + 检查接缝
    .venv/bin/python hk/build.py --check

    # 3. 色块底图（给模型看的输入，不是成图）
    #    water_fill() 刷平海面 -> 缩到 2400x1600 -> 中值 5 -> 量化 26 色
    #    存成 JPEG q92 再发给模型（PNG 的 base64 会让调用超时中断）

    # 4. 整张重绘 + 修水印 + 切瓦片
    .venv/bin/python hk/build.py --redraw hk/redraw.png \
      --corner-redraw hk/corner-redraw.png \
      --logo-box 1625,1103,1858,1238 --corner-dab 1800,1205,1858,1234,-70,-90

`build.py` 会写 `hk/plate.png`（原始底图）、`hk/redraw-clean.png`（修过水印的
重绘）、`hk/art.png`（成图）、`hk/tiles/`（z0..z2 瓦片），并把 `hk/map.html`
里的 meta 换成新的尺寸和版本号。

## 手绘效果是怎么出来的

第一版把**照片**直接丢给模型图生图，出来的还是"低像素照片"：颜色是渐变的，
每栋楼只是几个像素的色阶，没有线。描边后处理也救不回来——在 1858 像素宽的
整张图上，一栋楼才 2~4 像素，给 2 像素的东西描边，描完就是一坨黑。

真正的转折点是换掉**输入**：

    plate.png  ->  water_fill()       海面刷成一色
               ->  resize 2400x1600
               ->  MedianFilter(5)    抹掉摄影纹理
               ->  quantize(26)       塌成 26 个平涂色块

把这张色块图交给模型，它才画得出平涂色块 + 细墨线 + 手绘树 + 等深线，因为
输入里已经没有渐变可以模仿了。同一张底图、换个提示词，出来的就是插画。

三点要记住：

1. **只能整张一次出图。** 裁成几块分别重绘，模型会各自重新构图——它给的是
   "一张好看的香港"，不是"这块地的续画"。试过 6 块，两块相邻的输出里海面
   占比和楼群密度都不一样，接不起来。
2. **模型输出的水印在它自己画面的右下角，躲不掉。** 翻转输入没用（水印是
   后期盖上去的）。处理办法：先用底图上同一角再画一张（`corner-redraw.png`）
   贴掉主图的水印，剩下那 ~40x15 像素的角再用邻近的森林平移覆盖
   （`--corner-dab`，带羽化）。
3. **一次出图只有约 2.35 MPix。** 不管输入给多大，模型都给回 1872x1248
   左右。这是这张图 1858 像素宽的硬上限，也是细节到此为止的原因。

## 为什么之前的瓦片接不上

旧的一版是先渲染 4×4 共 16 张，**每张单独**送去重绘，再一张挨一张贴起来。
这违反了两条：

1. 相机。那 16 张是分别截的透视相机画面（`shots/hk-g*.png`），建筑在接缝
   处会错位、拉丝——顺着视线，远近不同的楼移动量不同。正交相机的光线互相
   平行，画面平移不产生视差，所以窗口能像素级对接。
2. 重绘。每块单独重绘，模型各画各的楼、各配色，路的颜色和屋顶样式在边界上
   就断了。必须一整张画布给模型看，或者按 blog 里的 MultiDiffusion 用重叠
   窗口共用同一个 latent；不能一块一块地重绘。

所以修法不是去"缝合"那 16 块——内容本身已经不一样了，缝不出来——而是回到
第一步，用一台正交相机重拍。

## 瓦片衔接

成图是**一整张**画布切出来的，所以瓦片之间本来就没有内容差异；会出问题的是
浏览器把它们放大缩小时各自的采样。原来的 `blit()` 把每块的目标矩形四舍五入
到整数像素，于是两块瓦片之间会差半个像素，而 `drawImage` 对每块瓦片单独做
双线性插值、到边缘就 clamp，结果每个 ≠1 的缩放比例上都会出现一条 1 像素的线。

修法就是 Deep Zoom 的老办法：**每块瓦片四周各多存 1 像素邻居**（512 → 514），
绘制时把这圈余量也画进接缝里，插值就有真实像素可取，不用 clamp。目标矩形同
时保持小数、不再取整。

怎么验证：打开 `hk/map.html`，把 `hk/seamcheck.js` 贴进控制台。它逐个缩放比
例去量瓦片边界那一列的「列间差」，再和左右 12 像素邻域的中位数比：

    留余量之前：scale 0.3 → 5254 倍     scale 0.7 → 6377 倍     scale 1.0 → 8806 倍
    留余量之后：全部 ≤ 1.21 倍（= 跟普通图像起伏一样，没有线）

比值几十以上就是一条孤立的线；≈1 就说明边界和别处没区别。

## 相机

朝向北偏西 15 度（`az=-15`），向下 45 度（`tilt=45`），
正交投影，1.1 米/像素。窗口 1024 像素，相邻窗口的相机沿画面的右、上两根轴
各平移 1024×mpp 米，所以接缝落在整数像素上。

水面上 Google 没有摄影测量，近岸是平的青色、外海是近乎黑的深蓝，两者之间
有一条硬边。`build.py` 先把水面统一刷成一个港口色，再送去重绘——不然模型会
把那条边照画成一条线。

## 待办

- 香港这张还没有动画（车、鸟、树、水波）。数据不在这个仓库里。
- 山上那些细线模型画成了偏蓝的溪流感，参照图里是偏灰的等深线。改提示词
  应该能压下去，但要重出一整张。
- 1858 像素宽是模型单次输出的上限。想更清楚只能换模型或上 MultiDiffusion。
